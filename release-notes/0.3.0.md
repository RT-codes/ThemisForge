## Themis 0.3.0

The biggest release so far. Work is now organised into workspaces and boards, workflows are further updated, can run branches of nodes in parallel and move work between boards on their own, and agents get more to work with.

### Upgrading

Run `themis upgrade`. It backs up first and goes back by itself if something fails. The database is migrated
automatically, and every task is moved onto a board: each project gets one workspace, **Main**, with one board,
**Tasks**, so nothing looks different afterwards. The **Inbox** status is now called **Backlog**. The upgrade also
gets the new agent image (see *Agents* below): it pulls it, or builds it on your machine if it cannot be pulled.

### Organise work

- **Workspaces and boards.** A project holds workspaces, a workspace holds boards, and every task lives on a board. Each
  board can add, rename, colour, reorder and delete statuses of its own, with an icon and a description of what each is
  for.
- **Move tasks between boards**, and create linked follow-up tasks on another board.
- **Task stages.** A task plays an ordered list of workflows, and a stage starts in the working folder the one before it
  ended in.
- **Working folders for tasks.** Continue in a task's folder, duplicate a task, and give a run a brief that every
  agent step of it is told to focus on.
- **Project history** at every level (project, workspace, board, task), and a **Needs attention** list on the project
  overview where a result can be opened directly.
- **A new project overview and a Settings page of its own**, with an icon and a purpose for projects and workspaces.

### Automate it

- **Connected automation.** A workflow's Trigger can start when a task moves into a status, and workflows can move and
  make tasks across boards, with a guard against loops (10 hops by default).
- **Halt.** Stop all work of a board or of the whole project at once. What was interrupted goes to Blocked, so resuming
  never restarts it by itself.
- **Branches.** A **Splitter** sends a run down 2 to 4 branches that run at the same time, and a **Merger** carries on
  once with all of them.
- **Parallel Codex runs.** Runs of one user share their Codex login side by side, up to a limit in Settings.
- **A better workflow editor.** A vertical flow, line styles, snapping, and saved nodes you can place again.
- **A workflow step can skip the task's goal**, and choose its own model and reasoning effort.

### Agents

- **Tools from a giant MCP registry can be added directly within themis**, including hosted tools you sign in to.
- **Connections.** Connect GitHub once and give an agent that login. The GitHub CLI is in the Codex image.
- **The Themis cell package.** A built-in skill that tells agents what a cell is and what it can do, editable in
  Settings without a rebuild. The Codex image now also holds Chromium (for agents that check a UI) and `uv`.
- **Model and reasoning effort** are picked from lists, per agent and per workflow step.
- **Busy models are retried**, and a failed run says why, with the last lines of its log.

### Reading results

- **An enlarged reading view** for an agent's result, and Markdown rendered in task and workflow history.

### Windows

- The installer checks that virtualization is switched on before it installs anything, and the README explains why
  Windows needs it.

### Fixes

- Cancelling a workflow run no longer leaves it waiting on its own write lock, and a cancelled run and its nodes are
  stopped before their cells.

## Everything that changed

The sections above are the highlights. This is the complete list.

### Added

**Workspaces and boards**

- Workspaces and boards, with a **Main** workspace and a **Tasks** board made for every existing project.
- A workspace page with its boards stacked (fold, move up or down, edit, duplicate, delete) and a board page of its own
  with Board, List, Schedule and History views.
- Duplicate a board (its statuses, without the tasks). Deleting a board or workspace asks where its tasks go.
- Statuses of your own on each board: add, rename, recolour, reorder, delete (with a destination for its tasks), give
  each an icon and a description shown in a tooltip. The seven built-in statuses stay locked. A status of your own is a
  parking column: the scheduler only acts on Ready and Running.
- Send a task to another board and status (not while it is running), or drag cards between the boards of a workspace.
  A status the target board lacks falls back to its Backlog.
- Follow-up tasks, linked to the task they follow, with a branch mark on the card and the links in the task panel.
- A board remembers its hidden columns, filters, sort and the height you gave it.
- A taskbar on every board with a count and an icon for each status, which pulses when the numbers change.
- Drag the handle under an open board to resize it, and double-click it to reset.
- Pick several cards (ctrl or cmd and click, shift and click for a run within a status) and move or delete them
  together. Click empty space to let go.
- Duplicate a task from the copy button next to the trash can. The copy lands in the Backlog without history, links or
  working folder.
- A task panel with a taskbar (board, status, Details and History), two tabs (General, Schedule & automation), and
  **Run now** in the top bar with when the task last ran.
- Icons for projects and workspaces, chosen from the whole Lucide set with a search box, and a purpose line for projects.
- Edit a project or workspace from the sidebar with the pencil that appears when you point at it.
- A sidebar with the pages grouped together and the workspaces as an indented branch below a **Workspaces** row.
- Appearance settings, and a project connections panel.

**Project overview and settings**

- A project overview that is only the dashboard: a header with the project's icon and main actions, task stats, **Needs
  attention**, **Upcoming runs**, a card for each workspace and a **Recent activity** timeline.
- **Needs setup**, a strip that lists agent files with problems, connections an agent wants that the project lacks and
  tools that need a sign in, each linking to the fix.
- A **Settings** page under every project with General, Cells and automation, Task properties, Agents, Workflows,
  Connections, Tools, Skills and Shared folders, and a danger zone to delete the project.
- Project history: tasks created and moved, and statuses created, renamed and deleted, with a workspace, board or task
  scope, a kind filter and paging. Everything a workflow does is recorded as "Workflow *name*", with the run and step
  that caused it.
- Open a task's result straight from **Needs attention**.

**Tasks and runs**

- Task stages: an ordered list of workflows per task, played one after the other in one attempt. A stage that fails ends
  the attempt, and the task's result rolls up the result of every stage.
- Stages on the ticket, as a list with status icons and, for the stage that is running, a small track of the node
  before, the node now and the node next.
- Working folders every attempt can continue: a stage starts in the folder the stage before it ended in, an Agent or
  Task node opts in with **Continue in the previous folder**, and agents are told what earlier steps changed.
- The task's title and description are given to every agent step as the brief, and the task panel shows each stage's
  step instructions with an **Edit step** link into the workflow editor.
- Stop a single task, or halt a board or the whole project.
- A run log that keeps the beginning and the latest output instead of stopping at a size cap, with long command output
  trimmed per command.
- Markdown rendered in task and workflow history, and an enlarged reading view for results.
- Every failed attempt keeps why it failed, what to do about it and the last lines of its log, shown on the ticket, in
  the task panel and in the history. Workflow steps pass theirs up to the run.
- An agent that cannot go on writes `/cell/blocked.md` with a reason and a fix, and the attempt fails with those words.
- Codex runs are started again after a provider error that is only temporary, with waits you set in Settings.

**Workflows**

- Triggers that start a workflow when a task moves into (or is created in) a status, including your own statuses, and
  can watch one workspace or one board. A run remembers the task that triggered it.
- Task steps that create their task on a chosen board, follow up the task that started the run, or send it to another
  board.
- The automation guard: every handling of a task by a workflow counts a hop and a person acting on it starts again, and
  past the limit the step stops with a reason. The limit and the start cooldown are layered Settings, project, task.
- Splitter and Merger, with a rule (only when the result contains some text) and a file filter on each branch, and an
  option to merge the branches that worked when one fails.
- A step that continues in the previous folder works on a copy, so branches side by side never write into the same
  files.
- Tasks that Agent nodes make for themselves are marked internal: hidden from boards and counts, and never start a
  workflow. **Show workflow steps** in a board's taskbar (off by default) brings them back.
- The workflow editor flows top to bottom, with connections that can be curved or angular, a snap to grid switch, a
  rounded minimap and saved nodes (up to 100 per project).
- A node window that opens beside the node and can be pinned, and Settings and Advanced tabs on the Agent window.
- An **Include task title and description** switch on Agent nodes, so a step that only does housekeeping (syncing,
  publishing) is not told to do the whole task.
- A **Model** section on an Agent node that overrides the agent's model and effort for that one run.

**Agents, tools and cells**

- Tools from the official MCP registry, browsable from a project's Tools, an agent's Tools tab and Settings, with a
  local copy of the catalog to keep search fast and packages pinned to the listed version.
- Sign in to hosted tools (Notion, for one) once; a run gets only a short-lived token, and a tool that is not signed in
  stops the run with a reason before any cell starts. The numbers are in Settings, Tool sign ins.
- Connections: encrypted per-user logins, starting with GitHub by device sign in, which an agent can opt in to.
- A **Cell package** in Settings: rules in every prompt and a `themis-cell` skill, editable and switchable without
  rebuilding the image, and listed (locked) on an agent's Skills tab.
- The Codex image gains the GitHub CLI, Chromium and `uv` (so tools on PyPI can start with `uvx`), and a newer Codex.
- A list of the models Codex offers, with the reasoning efforts following the chosen model. `xhigh`, `max` and `ultra`
  are valid efforts, and an effort a model does not accept falls back to the model's own default instead of failing.
- Up to a set number of Codex runs of one user at once (Settings, default 3). A run that may make Codex refresh the
  login takes it alone, and the runs after it share the refreshed one. A refreshed login is only kept when it is newer
  than the stored one, and a run refused with "refresh token already used" starts again once with the newer login, or
  says to connect Codex again.

**Windows**

- A check that virtualization is on before anything is installed, with the exact steps to switch it on, and a README
  that says it up front.

### Changed

- The **Inbox** status is now **Backlog**. Stored workflow graphs are rewritten to match.
- A task plays a list of workflows (stages) instead of one. Your existing workflow becomes its first stage.
- A project's tasks live in a workspace from the start, and the old `/tasks` address goes to the first workspace.
- The project dialog only creates projects. Editing is the General section of the project's Settings.
- A task arriving on another board in a Trigger's status starts that workflow.
- The agent page always shows Overview, General, Skills and Tools, with Delete, Discard and Save beside them.
- Older workflows with several lines on one connection point keep running one line after the other, and are drawn in
  amber.
- The built-in statuses have fixed icons, and icons are slightly larger and bolder throughout.
- The docs call the folder inside a cell the **work folder**, and describe workspaces, boards, history, stages,
  branches and connections.

### Fixed

- A cancelled workflow run could be left "running" for good after "database is locked", which also stopped its
  workflow from being deleted.
- Cancelling a workflow run could record the step it was stopping as failed instead of cancelled.

### Under the hood

- 17 database migrations (0012 to 0028), run automatically when the server starts after a backup. The
  whole chain was rehearsed on a database as v0.2.2 left it.
